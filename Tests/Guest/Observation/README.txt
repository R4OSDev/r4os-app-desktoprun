Explicit completion/output oracle (0.88.26)
==========================================
C-only fixtures use the public SDK. Build each module.R4MF through the normal
manifest builder and inject into a fresh private Desktop image. Neither is
an installed module. O26EDGE returns37; default/EMPTY/TRUNC/CLEAR waits for
Close; FAST emits and returns without its own frame. Normal stdout/stderr
are72source bytes /76normalized CRLF transcript bytes.

O26LIFE accepts exactly MODE<process-id>:<generation>:<window-or-observation-id>:
 D/P retain a default/portable binding, report its ID and end the creator;
 R adopts the reported binding, polls/read/releases it; T acquires a new late
 binding and also reports the old consuming owner-wait result;
 W runs an actual managed-thread pending wait while the main closes its token;
 V runs two actual waits while closing the GUI, joins and verifies owner reap;
 G retains twice, closes, reads before/after Desktop reap and releases each;
 K retains, requests exact-handle kill and reports the actual negative exit.
 I reports the old live/status/consuming API only.

The ordinary managed waiter thread reserves1MB. An earlier64KB fixture
exhausted its terminal guard during kernel stack preparation; it provides
no successful wait/cancellation or thread-fault-recovery claim.

portable creator-end, concurrent waits/cancel, actual owner consume, empty,
16384-byte truncation, clear/incomplete, actual kill(-9), fast late binding,
